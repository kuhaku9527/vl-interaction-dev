## 1. 因果链（Why / Why-this-choice）

### Problem

**本项目跑过大量测试，但结果没有落盘到可查的地方** —— 于是「跑过」与「没跑过」在证据上无法区分，
后人只能重跑或凭印象判断。这个缺陷已经**造成了实际损失**，有三类实证：

**① 同一命令，不同时刻得出相反结论，且无人知道该信哪个。**
2026-09-22 实测：`audit-frontend-residue.mjs` 在服务未起时报 **139 处死引用**，
在静态服务器就位后报 **0 处**。前者是**完全反向的假数字**，而脚本不报错、不警告。
工单 #144 正文因此挂着「13 处死引用待拍板」，而实测是 0。
⇒ **没有基线的测量，其输出无法被判断真伪。**

**② 「CI 全绿」被当作事实前提，而它只证明跑到的断言成立。**
已确认的 fails-open 实例至少四类（详见 `test-baseline.md` §6.4）：
`SRC` 唯一 import 通道且无守卫（#151）、46 个测试从未被收集（#152）、
6/7 个等价性断言恒真（#153）、计分器长期零覆盖（#155 复核发现）。
⇒ **没有「哪些断言在什么环境下绿」的记录，「绿」是不可采信的。**

**③ 关键数字在被推翻后仍在流传。**
例：`ctx 16384→4096 省 1,741 MiB`（按 f16 KV 算）在 q8_0 落地后实际只省 ≈918 MiB；
「决策从未落盘」实为**写入侧曾是假 no-op**。这些更正散落在各天 memory，**没有统一台账**。

同时，**三条链路从未有过真机证据**，却各有工单/文档在推进：
帧链路（摄像头/屏幕→VLM）、proactive 轮、多轮取中位。

### Why this choice

**把「证据」提升为一等交付物，而不是附属于某次工单的副产品。**

- 选**滚动台账**（`doc/standards/test-baseline.md`）而非一次性报告：因为问题不是「缺一份报告」，
  而是**每次实测都不落盘**。台账是唯一能持续吸收新增证据的形态。
- 台账**强制记录四件事**：命令、结果、**测量时间**、**真机还是离线**。
  这四项正是「139 vs 0」和「CI 绿 vs 裸跑红」两类事故的判别条件。
- 台账**必须收录失败、跳过与被推翻的数字**：只记绿的台账等于没有台账。
- **真机验证与离线测试分离记账**：二者不可互相替代（本项目已有 CI 绿而本地红、真机与静态结论相反的实例）。

### 被否方案及理由

1. **「写一份完整的测试报告」** —— 否决。报告是**事件型**（一次性），
   而缺陷是**流程型**（每次都不记）。报告写完即开始过期。
   （`doc/acceptance/` 已承担事件型验收，职责不重叠。）
2. **「把结果都塞进 memory」** —— 否决。memory 按天分文件、**不入库**、
   无统一口径，正是当前失效的形态（§6 的数字就是从 memory 里翻出来的，多数无命令无分母）。
3. **「靠 CI 绿作唯一真值」** —— 否决。已证 CI **可能比裸跑更宽松**（#151），
   且 CI 矩阵**不含** `services/scripts`、`asr`、`voice-clone` 等（#152）。
4. **「只记录通过的用例」** —— 否决。会把「因无关原因而通过」与「真通过」混为一谈，
   恰是本项目最贵教训的反面。
5. **「为三条未验链路各写一份独立 spec」** —— 否决。三者共享同一根因
   （**无真机证据 → 无基线 → 无法判断变化**），且共用同一套真机装置；
   拆开会让「装置」被重复建设三次。

## 2. 范围

### 做什么

- **A. 证据台账**（已起草，本次转正）：滚动记录测试/验收证据，含命令/结果/时间/真机与否/分母/口径。
- **B. 帧链路真机化**：摄像头/屏幕帧 → WS → VLM 的**端到端**验证，
  并对已观测到的「机制通、内容空」给出**判定**（缺陷 or 预期），建立**正常基线**。
- **C. proactive 轮真机化**：`LIVE_PROACTIVE_ENABLED` 打开后的真机行为与决策落盘。
- **D. 多轮取中位**：把单轮结论升级为**多轮中位 + 离散度**（#157 的硬要求）。
- **E. `delegate` 真机**：四态中唯一只有单测覆盖的一态。
- **F. 记忆写入端到端**：webinfer 自动 push → 召回 的真实链路（非手工 API）。

### 不做什么（负面约束）

- **不把「真机」当唯一标准**。离线单测是**更快更稳**的回归层；
  真机用于回答「真实链路是否通」，两者分工，不互相取代（否决方案 3 的延伸）。
- **不为「本地」或「云端」背书**。provider 选址（本地 / 云端 / 换厂商）是**可替换的选择**，
  不是约束；台账只记录**当时用的是哪个**（`ADR-0020` 已确立「本地/云端」为二选一 idiom，
  任何「必须本地」的表述都与该 ADR 冲突）。
- **不把运维状态写成缺陷**。例：MiniMax Token 额度用尽、edge-tts 端点间歇不可达
  —— 记为**事实与时间**，不立票（按用户口径：可替换的东西换了不算工作项）。
- **不重跑已有可信结论**。09-22 真机轮的结果（§1）可直接引用；
  §6 中「仅一行记述、无命令无分母」者才需重测。
- **不改被测对象**。本 spec 只建立**测量与证据**；产物缺陷（如「帧无 prompt」若判定为缺陷）
  走独立工单，不在此顺手改（同 #154 的「只造尺子，不动被测量物」）。

## 3. 设计（核心决策点）

### D1. 台账的形态与纪律（已完成，见 `doc/standards/test-baseline.md`）

- **滚动追加，不追改历史行**：数字变了**新增行**并注明覆盖关系（保留漂移轨迹本身即证据）。
- **每条必须四要素**：命令、结果、测量时间、真机/离线。
- **eval 类必须写分母**（已踩：25 vs 26 使跨变体比较静默失效）。
- **必须含「已推翻/已更正」专节**：防止过期数字继续被引用（§6.5）。

### D2. 三条未验链路共用一套**真机装置**

不为每条链路各造装置 —— 统一用**已在用的两个 MCP**（`ego_*` 浏览器自动化 + `computer_*` 桌面视觉），
原因：本项目的链路**起点在真实浏览器**（`getDisplayMedia` / `getUserMedia` / WebRTC），
自造装置已两次产出错误结论：

- 自建 `new WebSocket(...)` 发帧 → 只收到 `status`/`server_config`，**无 `vlm_response`**；
  改用**应用自己的 socket**（`window.websocket`）→ **收到 `vlm_response`**。
- 自建 `fetch('/offer')` 未带 `live_audio:true` → 落到 **jarvis** 分支；
  用户用页面真麦克风 → **走 live 且全链路通**。

⇒ **装置必须与用户路径同构**，这本身作为纪律写入台账。

### D3. 帧链路：先判定，再定基线

已观测（2026-09-22 首次真机）：链路**机制通**（帧送达、模型真被调用 `api_call_ms=416.5ms`、
响应经 WS 回传），但 `text = "Empty model response: stop"` 且 `metrics.user_prompt = ""`。

**设计决策**：本 spec **只要求判定并建立基线**，不预设结论。判定须回答：
帧路径**是否本应自带视觉提问**（对比 `captureBtFrameB64` 的纸飞机路径，那里是显式带文字提问的）。
判定依据取自**决策态**（`doc/subsystems/screen-capture.md` / `live-visual-cb.md` §1 的承诺），
而非实现现状。

### D4. proactive 轮：必须打开 env 门才能测，且需与「不干扰对话」同时验

`LIVE_PROACTIVE_ENABLED` 默认 OFF（`live_proactive.py:64`），故从未真跑。
设计约束：打开后须同时验证**约法三章**（主动搭话不得干扰用户对话）—
即 `turn_state != LISTENING` 时跳过、用户开口时让路。

### D5. 多轮取中位：把「轮数」与「离散度」变成结果的一等字段（已完成，工单 #165）

已知单轮样本不足（26 例非面向中 12–14 例两轮不一致）。设计：
结果结构必须含 `rounds` 与离散度；**中位数与单轮值并列**，不得只报其一。

**实现落点**：`services/webinfer/decision_eval_rounds.py`（CI 可见、有单测）
+ `services/scripts/benchmark_production_live_prompt.py` 的 `BENCH_ROUNDS`（默认 3）。

**实测补充（2026-09-22，三轮）**：离散度给出的结论比预期更强 ——
误响应率的 stdev 达 **5.4–7.2 个百分点**、nfm 召回 **1.8–3.6**，
且 56 句里有 **29–31 句跨三轮决策不一致**。
⇒ 此前所有单轮得分都应视为**该分布的一次抽样**，而非能力的点估计。

**两处由真机暴露的补充设计**（不在原设计里，实测后才加）：
1. **分母退化必须被点名**：分母为 0 时 `summarize` 把比率记 `0.0`，
   与「测了但全错」**数值相同、含义相反**（真机撞到精确率 stdev 虚高 47.14；
   存量历史文件撞到 `delegate_recall=0.0` 其实是「当年没测」）。
   ⇒ `metrics_note.degenerate_rounds` + 逐条登记分母的 `RATIO_DENOMINATORS`。
2. **跨 CI 边界的契约必须有离线守卫**：`services/scripts` **不在** pytest 矩阵内
   （也不在 ruff 范围内），一次结果块键名不匹配在**跑完 336 次推理后**才崩
   （≈7 分钟白跑、文件零字节）。
   ⇒ 组装抽成纯函数 + 静态 AST 扫描 `main()` 的下标读取
   （``tests/test_benchmark_multiround_contract.py``）。

**`/code-review` 两轴随后查出的 6 处**（各自跑了变异测试），其中三处属本节同一病根：
- **「0.0 = 测到 0 还是没测」再次出现**，这次在**成本**字段：从已落盘文件重聚合时
  没有耗时数据，实现用 `[0.0]*n` 填充 ⇒ 报告声称「单轮 0.0 秒」。
  ⇒ 统一 `None` + `measured: false`。
- **守卫本身恒真**：`RATIO_DENOMINATORS` 的守卫只断言「分母是某个已聚合指标」，
  对 3/5 条比率恒真 —— 把三条分母改错**全绿通过**。⇒ 独立金标 + 行为正/负控，
  三个变异体逐一实测被杀死。**这是 §1「CI 全绿 ≠ 断言有效」在本票内部的复现。**
- **静态扫描漏嵌套层**：`payload["rounds_report"]["case_stabilty"]` 扫不出，
  而 docstring 声称守「整类」⇒ 改为递归校验，并**如实写明覆盖边界**。
另三处：CRLF 污染（`Path.write_text` 在 Windows 的默认行为）、
`BENCH_ROUNDS=1` 被静默改成 2、两处自述不实（含指向不存在的键）。

### D6. 每个新判据配负控（继承 #154 / #151 的硬约束）

「判据能跑绿」≠「判据能分辨对错」。每条新判据须有一份**故意做错的输入**证明它会**判红**。

## 4. Harness（条件满足，保留）

> 触发条件：本 spec 的实现/验证涉及**跨 ≥2 任务复用**的流程，且是**必须被原样复现的仪式**
> （真机联调需要 6 服务 + 浏览器 + 桌面，装置搭建成本高）。

### 4.1 真机装置（可复现工作流）

```
# 1) 起栈（6 服务）
powershell -NoProfile -ExecutionPolicy Bypass -File start-joyai.ps1 -Mode default
python services/scripts/verify-services.py          # 期望 ALL GREEN

# 2) 静态服务器（审计脚本与部分 UI 脚本需要；缺失会导致假数字，见 §1 ①）
cd services/webui/src/joy_interaction_webui/static
python -m http.server 8123 --bind 127.0.0.1         # 必须服务**这个**目录

# 3) 浏览器/桌面（用 MCP，不自造装置）
ego_status → ego_space_open(default) → ego_navigate(http://127.0.0.1:8099/)
computer_screenshot                                  # 需要真实桌面帧时

# 4) 真机门禁
python scripts/drift_gate.py --contract config/drift-contract.json --phase runtime --mode closed
```

### 4.2 验证仪式（每次真机轮必跑，结果进台账）

| 步骤 | 命令 | 判据 |
|---|---|---|
| 栈就绪 | `verify-services.py` | ALL GREEN |
| 运行时门禁 | `drift_gate … --phase runtime --mode closed` | `block_fail=0` |
| 前端残留 | `node scripts/audit-frontend-residue.mjs` | **需 8123 就位**；否则数字无效 |
| 路由契约 | `node scripts/audit-api-contract.mjs` | `BROKEN=0` |
| live 决策 | `python -m decision_events`（services/webinfer） | 有事件且 `latency_ms`/`session_id` 非空 |
| 向量召回 | `python tools/eval_golden_recall.py --mode vector`（需 `SILICONFLOW_API_KEY`） | `recall@5` 报告值与分母 |

### 4.3 注意

- harness 是「让机制替人盯」的脚手架，不是业务算法描述。
- **AFK 边界**：台账追加、单测、离线可复现部分 = AFK 可做；
  **需要真实麦克风/真实桌面的部分需人在回路**（HITL），命令给出后由用户执行或使用 MCP 浏览器。

## 5. 验收 / 排除

### 验收判据

1. 台账存在、LF、被 `doc/README.md` 索引（`doc_health --check index` 无新增死链）。
2. 台账含 §1（当日证据）、§4（欠账清单）、§5（易误判的分工）、§6（历史回溯 + 被推翻数字）。
3. 三条未验链路（帧 / proactive / 多轮）**各自有真机结果行**，且**写明判定**。
4. `delegate` 与记忆端到端**各有一条真机结果行**。
5. 每条新判据附负控证据。
6. 所有结果行含**测量时间**与**真机/离线标记**。

### 明确排除

- **bug 修复**、**运维操作**不属本 spec（见 `决策/spec编写规范.md` §3）；
  产物缺陷走独立工单。相关 runbook：`doc/standards/test-baseline.md` §4。
- **不在本 spec 内改被测对象**（provider 选型、prompt 调优、模型替换均另案）。
- **不复活历史遗留**：`#150`（eslint 收窄）、`#152`（CI 矩阵盲区）已独立存在，不并入。
