## 1. 背景与目标

- live 模式常驻实时交互，有沉默判定（silence），但**缺少"持续闭嘴"的判定**：
  玩家抗高压环境（boss 战/专注操作）时 BT 说话会干扰。
- 目标：给 live 增加**「无线电静默」（Radio Silence）**子状态——存在但隐身：
  不推理不播报，只留可配置的唤醒通道。产品语义：陪伴 → 隐身 → 被召唤。
- 命名：**无线电静默**（真实军事术语，契合 BT-7274 军用泰坦身份）。
  触发命令："无线电静默" / "静默"（完整短语匹配；BT/静默非常用词，不做误触/被提起区分）。

## 2. 状态机

```
┌─────────────┐   唤醒三通道（KWS 若开 / 组合键 / 语音）  ┌──────────────┐
│  live 常驻态  │ ─────────────────────────────────────► │ 无线电静默    │
│  四态决策+播报  │ ◄───────────────────────────────────── │ 存在但隐身    │
└─────────────┘  触发：语音命令 / 组合键（切换式，非按住）  └──────────────┘
```

- **静默是 live 的子状态**，不是新模式（不破坏 D-001 三模式隔离）。
- 静默态行为：模型推理停、TTS 播报全抑制（比 `force_silence_before_query` 更彻底——
  那是"无 query 才静默"，这是"有 query 也不响应"）；视觉继续（画面照常进，唤醒时知道
  发生了什么——**隐身观察**）；记忆按 ASR 开关决定。
- **持久性**：静默不跨重启，重启默认回 live 常驻（防"忘了开静默变哑巴"）。

## 3. 设置项（前端设置面板，全部配说明文字）

| 设置项 | 类型 | 默认 | 说明 |
|---|---|---|---|
| 静默组合键 | 自定义（键盘） | `Ctrl+Shift+S` | "按此键切换无线电静默" |
| 静默态 ASR | 开关 | 关 | "开：静默期间继续转写记录记忆；关：更省算力" |
| 静默态 KWS | 开关 | 开 | "开：喊名字可唤醒；关：仅组合键/语音唤醒" |
| 静默超时提示 | 开关 + 分钟 | 开，15 分钟 | "静默超时后 BT 提示一句'仍在静默中'" |
| 静默自动唤醒 | 开关 + 分钟 | 关 | "超时后自动退出静默（防忘记关闭变哑巴）" |

- **不做手柄适配**（手柄键太少）。
- 静默期间的状态角标/弹窗指示 → **后续任务**（大工程，需配套前端弹窗，已入任务列表）。

## 4. 静默态 ASR × KWS 组合矩阵（自由搭配）

| ASR | KWS | 行为 | 唤醒通道 |
|---|---|---|---|
| 开 | 开 | 记忆连续 + 双名字通道 | KWS / 文本层 / 组合键 / 语音 |
| 开 | 关 | 记忆连续 + 精简 | 文本层 / 组合键 / 语音 |
| 关 | 开 | 纯省电 + 声学雷达 | KWS / 组合键 / 语音 |
| 关 | 关 | 最省电 | 组合键 / 语音 |

**唤醒三通道兜底（常驻）**：KWS（若开）/ 组合键 / 语音命令——三条路，绝不"叫不醒"。

## 5. 唤醒仪式

- 唤醒回应：**替换 `prompts/bt/events/wake.wav` 为语音版"我在，铁驭"**（复用 jarvis
  现有 `_play_wake_wav` 播放机制，`jarvis_state.py:21` WAKE_DETECTED，零 token）。
- 静默态名字命中 = 解除隐身（比常态"被点名"语义更强，响应可更正式）。
- **无唤醒汇报**：静默期记忆（若 ASR 开）由用户主动询问召回（"BT，刚才我打 boss 时
  说了什么"→ 本地 wiki recall）。
- 名字检测共用：常态叫名字=确认；静默态叫名字=唤醒（同一引擎，状态不同语义不同）。

## 6. 静默超时逻辑

```
进入无线电静默 → 启动计时器
  ├─ 超时 T1（静默提示，默认开=15min）→ 播预录提示音/一句"仍在静默中"（不打断专注）
  └─ 超时 T2（自动唤醒，默认关）→ 自动退出静默回 live 常驻
两个开关独立、分钟数独立；T2 关闭时只能靠手动唤醒（KWS/组合键/语音）
```
