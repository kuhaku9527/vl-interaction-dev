# Spec：WebUI 元件一致性纪律（草稿）

> 生命周期标记：`<草稿>`
> 作者端点：`<前端>`
> 关联：`doc/subsystems/voice-ui.md` §9 Design Tokens（上游 token 源）、`决策/<WebUI 元件一致性>`（待审查组 ratification）
> 合规：本 spec 套用 `决策/spec编写规范.md` 四要素（因果链 / 条件 harness / 负面约束 / 生命周期标记）。

## 1. 因果链（Why / Why-this-choice）

- **Problem**：`voice-ui.md` §9 已规定 voice HUD 状态徽章**必须**复用 token / 语义色 / 8px 网格，但**范围仅限 voice HUD**。WebUI 其他表面（主视图 header、设置弹窗、状态指示区）无同等级约束。结果 2026-08-16 设置弹窗重设计时，前端自造 `.qt` 裸文字状态标签 + 新配色，破坏 header（`.health-pill`）/ 主视图（`.chip` telemetry）/ 健康菜单（`.svc`）既有的视觉语言统一，连续三轮返工（v6-lite → v6-lite.2 → v6-lite.3）才收敛。用户原话：「ui 元素要统一」「后面跟着的状态说明呢，是否激活，激活了哪个？用户不清楚」。
- **Why this choice**：把 §9 的「复用 token、禁止散落」原则**提升为跨所有 WebUI 表面的硬约束**，并显式列出「禁止自造新元件形态」。元件一致性是全局视觉契约，不该按表面各自为政。
- **被否方案及理由**：
  ① 仅依赖 §9（范围窄，漏掉设置弹窗 / header）→ 已证失败（见上）；
  ② 每个新表面各自写样式约定 → 漂移、重复、不可比对，否决；
  ③ 靠代码 review 人工盯 → 不可靠（本次就是 review 没拦住自造 `.qt`），否决。
  → 选「一份跨表面 spec，绑定 §9 token + 显式元件复用白名单 + 负面约束」。

## 2. 范围

- **做什么**：定义 WebUI 全表面（主视图 / header / 设置弹窗 / 状态指示区）的**元件复用**与**状态色一致性**硬约束；给出「已有元件白名单」与「禁止清单」。
- **不做什么（负面约束）**：不改动 §9 既有 token；不引入 CSS 框架；不规定具体业务布局（本 spec 只管**元件形态**与**状态色语义**，不管排版）。

## 3. 设计（核心决策点）

- **D1 元件复用白名单**：状态 / 指示类元素只能从以下既有 class 取，**禁止新造形态**：
  | 用途 | 既有 class | 出处 |
  | --- | --- | --- |
  | 语义状态点 / 徽章 | `.status-badge` 系列 | voice-ui.md §9.1 |
  | 轻量信息 chip（状态点 + 文字） | `.chip`（主视图 telemetry：MIC / ASR / LLM / TTS / E2E） | index.html |
  | 列表式状态行（点 + 名称 + 状态文本） | `.svc`（健康菜单） | index.html |
  | header 健康总览 | `.health-pill` | index.html |
  - 新增表面需要新形态时，**先在本 spec §3.1 追加白名单**，禁止在 PR 里临时造。
- **D2 状态色语义**（直接复用 §9.1，不得新造色值）：**绿 = 健康 / 已连接 / 激活**，**黄 = 未知 / 警告**，**灰 = 未连接 / 未激活 / unknown**，**红 = 错误**。状态必须用语义色表达，不得用单一品牌色家族铺满。
- **D3 禁止裸文字状态标签**：不得用无边框 / 无圆角 / 无状态点的纯文字（如已删的 `.qt`）表达「是否激活 / 激活了哪个」——必须带状态点（D1 白名单元件自带）。状态说明缺口用 `title` 悬浮 / 列表文本补足，而非裸文字。
- **D4 间距 8px 网格**：所有 WebUI 表面间距走 8 / 16 / 24px 基准，禁止非 8 倍数 gap / padding（继承 §9.3）。
- **D5 字体归属**（继承 §9.2）：机器文本（状态 / 日志 / 时间戳）走 mono；正文 / 对话气泡走 Inter；不得混用导致层级混乱。

## 4. Harness（仅当满足条件才存在）

> **触发条件**：满足「跨 ≥2 表面复用」→ 保留本节。

- **验证仪式**：新增 / 改动 WebUI 状态类元素的 PR，**必须在描述里引用本 spec + voice-ui.md §9**；reviewer 核对：① 是否用了 D1 白名单元件；② 状态色是否来自 §9.1；③ 间距是否 8px 网格；④ 有无裸文字状态标签（D3）。任一不符 → 打回。
- **静态护栏（建议，非强制）**：在 `services/webui/static/` 加 lint，禁止出现未在本 spec §3.1 登记的新「状态指示」class 命名（`*status*` / `*badge*` / `*chip*` / `*pill*` 前缀须命中白名单）。

## 5. 验收 / 排除

- **验收判据**：
  ① 本 spec 列入 `AGENTS.md` onboarding 必读（与 voice-ui.md §9 并列，由审查组 / lead 落地）；
  ② 设置弹窗 redesign（`design/joyai-redesign-preview.html`）已对照 D1–D5 自查通过（jarvis 激活绿点、live/kws 灰点、复用 `.chip`、无 `.qt` 残留）；
  ③ 后续 UI PR 描述引用本 spec。
- **明确排除**：具体业务布局 / 交互设计不属本 spec（见 `决策/spec编写规范.md` §3）；相关 runbook 见 `doc/subsystems/voice-ui.md` §9。
