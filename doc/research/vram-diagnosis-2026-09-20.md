# 显存诊断（2026-09-20）—— 哪里占得多、哪块还能压

> 方法：从干净桌面（446 MiB）逐个拉起服务并测增量（差分法）。
> 安全阀：内存 <4GiB 或显存 <1.5GiB 立即中止。全程无异常。
> 权威数字来自 llama.cpp `-v` 自报，非推算。

## 一、当前显存总账（KV q8_0 已落地）

| 项 | MiB | 来源 | 可压性 |
|---|---|---|---|
| **LLM 权重 IQ4_NL** | **4,232** | `CUDA0 model buffer size`（自报） | ⚠️ **最大单项** |
| **KV cache q8_0** | **1,224** | `K (q8_0) 612 + V (q8_0) 612`（自报） | ✅ 已从 2,321 压下 |
| **compute buffer** | **516** | `144.09 + 372.08`（自报） | ❌ 运行时必需 |
| **mmproj F16** | **~1,483** | 实测增量反推 | ✅ **有压缩空间** |
| CUDA context / 其他 | ~200 | 余项 | ❌ |
| **llama-server 实测稳态** | **7,664** | 差分实测 | |
| 桌面基线 | 446 | 差分实测 | |
| **合计占用** | **8,110** | | |
| **16,311 − 8,110 =** | **8,201 MiB（8.0 GiB）** | **给游戏剩余** | |

## 二、mmproj 为什么占 1,483 MiB（文件只有 1,105）

实测张量汇总（352 个张量）：
| 精度 | 大小 |
|---|---|
| **f16** | **1,093.4 MiB** |
| f32 | 11.9 MiB |
| **合计** | **1,105.3 MiB** |

**⇒ 文件 1,105 MiB，但显存占 ~1,483 MiB，差额 ~378 MiB 是 CLIP compute buffer**（不随权重量化缩小）。

## 五、若要进一步（可选）
先做 mmproj Q8_0（第 1 条，~400–540 MiB，风险低）。**权重更激进量化（第 2 条）须权衡质量**——
但注意用户原话：「就算回答错了也无所谓，纠错就好了，有文本知识库」。

## 六、不确定项（诚实标注）
- mmproj F16→Q8_0 的**视觉精度影响无任何公开实测**，转换后必须自测
- 本诊断只测 llama-server 单进程；**其余 5 个服务（webinfer/webui/agent/voice-clone/memory-store）均为 CPU 侧**，不占显存
- compute buffer 的 516 MiB 会随输入长度增长，长会话下可能更高
