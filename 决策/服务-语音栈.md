- **事实**: 用户拍板（2026-09-19）：

- **实现**:

      `needs_api_base`/`supports{voice,rate,pitch,emotion}`）+ 各 provider 音色列表

  - 前端 `config_services.js` 新增 `wireTtsControls()` / `previewTts()`；
    `app_main.js` 初始化处调用。

  `api_key`/`model`/`provider`，其余 4 个槽位都有，**唯独 TTS 的 HTML 漏了这两个输入框**
  —— 属遗漏而非设计决策，本次补齐。
- **"厂商参数不统一"的处理（本期）**: 用 **provider 能力表驱动显隐** ——
  选 Edge 时 Key/Model/Base 三组**整组隐藏**（它是内置通道，不走自建地址），

     导致 `wireTtsControls()` 静默失效（**无任何报错**，最难查）。
     修法：一律**延迟取值**（函数内 `getElementById`），不在 IIFE 顶层缓存 DOM。

## D-2026-08-08-080  ASR 外部端点不可达：显式报错，禁静默降级本地 sherpa

- **背景**: webui `asr.py` 的 `asr_websocket_handler` 原对 `connect_asr` 的**任何**失败（含 url 配了但连不上 / 401 / url 空）统一 `except Exception` 静默接进本地 in-proc sherpa，且只用 `logger.info`（非 error），浏览器端还收到假 `connected` 状态。违反约法三章②「禁静默 fallback」，且外部 ASR 真实宕机时操作员无感知 → 埋雷。
- **决策**:
  1. **url 未配置 = 本地 in-proc sherpa 是默认主路径**（非 fallback）：显式 `logger.info("local in-proc sherpa ASR (no external endpoint configured)")`，行为不变。
  2. **url 已配置（外部 ASR 为主）但不可达 / 鉴权失败 = 显式错误**：`logger.error(...)` 告警操作员，且向浏览器发送**显式 degraded/error 状态**（非假 `connected`）；默认**不静默降级本地**。
  3. 若确需 failover 到本地作为降级，**必须 `ASR_ALLOW_LOCAL_FAILOVER=1` 显式 opt-in**，且触发时 `logger.error`（非 info）+ 客户端状态标记 `degraded:true` + `reason:"external-asr-unreachable"`（结构化，与实现一致），让操作员与用户都看得见。
- **依据**: 约法三章②（异常要么 raise 要么 log+显式错误态，禁静默 fallback）；用户 2026-08-08 明确「外部云不行应该报错提醒，fallback 了也没拉起来服务还不报错=埋雷」。
- **预期**: 外部 ASR 配了但挂 → 日志 error + 客户端可见错误/降级，运维立刻发现；未配 → 本地静默正常（本就设计如此）。
- **Owner**: 后端
- **锁定**: 🔒
