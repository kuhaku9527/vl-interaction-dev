## D-2026-07-26-006  GitHub 操作走 gh CLI（直连，不用 gh-proxy）

- **事实**: 本项目 GitHub 操作统一走 `gh` CLI；`gh` 已登录 `github.com`（account `kuhaku9527`），token scopes 含 `repo` + `workflow`。
  **2026-09-14 按实测重写**（原 4 点中 3 点为 WorkBuddy 环境特定，已移出）：
  1. **remote 直连** `https://github.com/kuhaku9527/vl-interaction-dev.git`，**不设任何 `insteadOf` 重写规则**（实测 local/global 两层均无）；`gh-proxy` 已废弃——代理会顶掉 VPN。
  2. 推 **workflow 文件**（`.github/workflows/*`）需 token 带 `workflow` scope —— 当前 keyring token **已含**，无需 fine-grained PAT。
  3. 遇推送失败：先 `gh auth status` 看 scope，再确认 VPN 连通；**不要**急着加 insteadOf 或换 MCP 通道。
- **来源**: 主理人实测 2026-07-26~28（原版）+ **2026-09-14 按当前 git 配置重核**；`docs/github-runbook.md`（GitHub 操作的 SSOT）
- **校验**: `git config --get-regexp insteadof`（应 **无输出**）；`gh auth status`（应显示已登录 + scope 含 `workflow`）
- **预期**: 无 insteadOf 规则；gh 已登录；workflow 可直接推送
- **Drift**: 原条目写"push 必须走 gh-proxy insteadOf、须 fine-grained PAT"——**与 2026-09-14 实测不符**（无任何 insteadOf 规则，keyring token 已含 workflow scope）。`docs/github-runbook.md` §1 的"禁用 gh-proxy"与实测一致，本条目原版与之矛盾，现按实测统一。
- **环境备注**: 原条目含 `dangerouslyDisableSandbox:true`（WorkBuddy 独有开关，DSH 无此概念）→ 已移出，见 `doc/history-agent-environments.md` §1。各环境实际推送方式见 `docs/github-runbook.md` 的「环境分支」段。
- **Owner**: DevOps
- **锁定**: 🔒
