# AI 代码质量约法三章（跨域铁律）

> 立约日：2026-08-03｜by AI｜approved: 用户（口头明确要求「必须要约法三章」）
> 适用范围：所有 AI agent（含本 JoyAI 研发团队各角色）对本仓库代码的任何改动。
> 配套：模块 log 规划见 `决策/服务-日志.md`（D-060~062）；旧活儿接手见 `doc/old-work-takeover-todo.md`。

---

## 立约背景（用户复盘的原话要点）

AI 生成代码的通病：
1. 不符合开发流程规范，**极度防御激进**——喜欢搞莫名其妙的非空判定，必需存在的组件也要判空，**以「糊弄编译器/类型检查器不报红」为核心优化目标**。
2. 难读、难维护；问题累积到后期，**一切以「当前看不出有什么问题」为核心**。
3. **静默返回**、出了问题 `continue` 的——后期不爆红但看不出问题，因为问题被静默吞了。
4. 判空**无报错、无 log、就静默返回**；业务上必须存在的东西，它判个空做什么？
5. 增加新功能 / 优化时**不删旧代码**，把屎山堆着。

---

## 第一章　不写防御性判空

- **禁止**在任意模块（含核心服务 `webinfer` / `webui` / `asr` / `tts` / `memory-store` / `background-agent` 的业务逻辑）里**擅自添加非空判定 / try-except 兜底 / 防御分支**，只为消除编译器或类型检查器的红线。
- 必需存在的组件（配置项、依赖服务、必填参数）**不得判空后静默降级**——缺失即报错，宁可启动失败也别带病运行。
- AI 可以改动任何文件以修复 bug、接手旧活儿；但每次改动都须遵守本约法（不静默、必 log、增新删旧）。涉及架构 / 不可逆的大改动，先写 spec+adr 框定范围再动手（见 `doc/old-work-takeover-todo.md` 的接手流程）。

## 第二章　禁止静默返回 / 禁止 fallback

- 函数遇异常、空值、分支不可达时，**不得** `return None` / 裸 `return` / `pass` / `continue` 且无任何日志。
- **禁止 fallback**：找不到 A **不得**静默用 B 兜底。例如 `.env` 缺失静默回退 `.env.example`——2026-08-02 PR #65 里曾加过该回退，**已于 PR #67 移除**，改为主动报错 `exit 1`（即本条要求的合法路径）。
- 异常的处理只有两条合法路径：
  1. **向上 raise**，让调用方知道；或
  2. **log（error/warn）+ 显式返回错误态**。
- **绝不允许「看不出问题」的静默路径**。

## 第三章　日志与代码卫生

### 3.1 必须有日志
- 每个关键路径、分支、异常点必须有日志记录，遵循 `决策/服务-日志.md`（D-060~062）的 JSONL 事件 schema：四必填 `ts` / `level` / `service` / `event`。
- PII 红线（D-061）：日志不记 request/response body、raw key/token、文件内容、client IP。

### 3.2 日志定时提取与清理（三天一轮）
- **提取（有痕迹）**：每三天从 `logs/events/*.jsonl` 提取关键事件留存到可追溯位置（如 `分析/` 或审计目录）；**提取动作本身留痕**（记一笔「何时提取了什么」），便于回溯。
- **清理（防污染 + 防误判）**：超过保留期的日志 / 临时文件定期清理，避免污染工作树、避免被误读为当前状态。

### 3.3 模块 log 基础设施补齐（约法三章生效的前提）
- `services/` 当前**零日志基础设施落地**（grep `get_logger|module_logger|setup_logging|structlog` 全无命中），只有 `决策/服务-日志.md` 规划。
- 按 D-060~062 补齐：logger 接入（各服务 emit JSONL）+ `scripts/log_query.py` 实现（⚠️ 2026-09-14 核查：该脚本仍未落盘，见 `doc/README.md` 已知文档债 #7）。<!-- known-absent -->
- 这本身就是最高优先的旧活儿（`doc/old-work-takeover-todo.md` ① `feat-q2-emit` = ADR-0014 接线进 webinfer/memory-store/webui）。

### 3.4 增新 / 优化必须删旧
- 增加新功能或优化现有功能时，**必须删除被取代的旧代码 / 旧分支 / 旧配置**，禁止新旧并存堆屎山。
- 删旧前先 `grep` 全仓确认零引用再删；有引用先迁移再删。
- 分支管理同理：做完即合、即删，不堆叠（见 `doc/old-work-takeover-todo.md` 的接手流程）。

## 验收 / 门禁

- **code-reviewer 审查**时把以下列为 **BLOCKING**：
  - 静默返回（`return None` / 裸 `return` / `except: pass` 无 log）
  - 无理由的 fallback / 静默降级
  - 关键路径无日志
  - 新增代码未删被取代的旧代码
- **CI 后续加 lint rule**：检测 `except: pass`、静默 `return None`、fallback 模式（参考 D-061 PII lint 做法）。
